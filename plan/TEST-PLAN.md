## 1. 概述

### 1.1 编写目的

- 为骁骁TV（EvoKids）v1.5.0 的功能验收、专项测试与发布决策提供统一的测试依据；
- 定义测试范围、策略、环境、准入/准出标准、缺陷管理流程；
- 提供覆盖全部功能模块与关键异常场景的**160 条**测试用例，作为执行与回归的基线。

### 1.2 项目背景

骁骁TV 是面向小学生的 B 站英语动画/纪录片**白名单播放器**（Android TV / Leanback，D-pad 遥控操作）。孩子只能看到家长通过服务器配置的片单（1041 部，L1~L5 分级 + 纪录片）；家长扫码登录 B 站后应用内直接拉流播放（DASH 1080P，失败降级 MP4 直链），支持英中双语字幕（CC 轨优先，无轨时 Vosk 离线实时英文识别）。

产品核心承诺（测试必须守护的三条底线）：

1. **白名单闭环**：应用内不存在任何站内搜索、推荐、相关视频、任意视频入口，孩子无法看到片单之外的内容；
2. **永远有片单**：配置三级来源 + 本地缓存兜底，任何网络/服务器故障下孩子都能看到"最后一份成功加载的片单"；
3. **零门槛使用**：无 PIN、详情页 3 秒无操作自动起播、播完自动连播——孩子拿遥控器即看。

### 1.4 术语与缩写

| 术语 | 说明 |
|---|---|
| 白名单 | `config.json` 中 `categories[].items[]` 定义的全部影片，孩子可见内容的唯一来源 |
| 三级配置来源 | ① 设置页输入的自定义地址 → ② APK 内置默认地址（`BuildConfig.DEFAULT_CONFIG_URL`）→ ③ 内置离线片单（`assets/config.default.json`，365 部）→ ④ 上次成功缓存（SharedPreferences） |
| BV 号 | B 站视频唯一标识（`BV1xx…`），配置可预置（`item.bvid`），缺失时用搜索词 `item.kw` 现场解析并缓存 |
| 分P / cid | B 站视频的多集结构；`item.ep` 指定第几P，cid 为该P的播放标识 |
| qn | B 站清晰度档位代号（127=4K、116=1080P60、80=1080P、64=720P 等） |
| DASH / MP4 直链 | 两条拉流路线：登录态优先 DASH 音视频分离流（可达 1080P+），否则 HTML5 MP4 直链（游客最高 720P） |
| CC 轨 / AI 轨 | B 站字幕轨；`en`/`zh-CN` 为 CC，`ai-en`/`ai-zh` 为 AI 生成（需登录） |
| Vosk | 设备端离线英文语音识别（assets 内 41MB 模型，首次使用解压），为无字幕轨视频实时生成英文行 |
| D-pad | 遥控器方向键 + OK 键的 TV 交互模式 |
| P0/P1/P2 | 用例优先级，见 3.3 |

### 2.2 测试内容（In Scope）

- 功能测试：M1~M9 全部功能点，正常流 + 异常流 + 边界值；
- 白名单与儿童安全专项（产品底线，单独成组用例）；
- 接口契约测试：B 站 web 接口的请求参数、请求头（Referer/Cookie）、返回码处理、poll 状态机；
- 配置专项：三级来源优先级、版本回退保护、损坏数据容错、v1/v2 双格式；
- 性能测试：冷启动、起播时间、千部片单滚动、Vosk 延迟、长播内存；
- 兼容性测试：API 21~35、分辨率（1080P/4K/65寸）、abi（arm64-v8a / x86_64）、纯 D-pad 操作；
- 稳定性测试：断网/弱网/风控限流、快速操作、Monkey、24h 长跑；
- 升级测试：覆盖安装状态保留、卸载重装清空；
- 构建与 CI：本地 assembleDebug、GitHub Actions 出包、片单脚本。

### 2.3 不在本期范围（Out of Scope）

- B 站服务端自身的功能与性能（只验证客户端对接口的容错）；
- 大会员 4K 画质完整验收（无大会员测试账号，仅在有条件时执行 COMP-008）；
- iOS/手机端、平板触屏体验优化（应用声明 touchscreen 非必需，手机侧载仅验基本可用）；
- 单元测试/自动化框架搭建（本计划以手工+脚本辅助为主，自动化建议见 9.3）。

## 3. 测试策略

### 3.1 测试类型与分层

| 层级 | 测试类型 | 方法 | 工具 |
|---|---|---|---|
| L1 | 静态检查 | 代码走查重点：空指针/协程取消/资源释放；Manifest 权限与导出组件审查 | 人工 + `aapt dump badging` |
| L2 | 接口/契约测试 | 直连 B 站接口验证参数与响应处理；中间人抓包验证请求头 | curl、mitmproxy/Charles |
| L3 | 系统功能测试（主体） | 黑盒 + 场景驱动，按第 8 章用例逐条执行 | adb、遥控器/模拟器按键 |
| L4 | 专项测试 | 性能、兼容、稳定（Monkey/长跑）、安全、升级 | monkey、`dumpsys meminfo`、Python 限速脚本 |
| L5 | 探索性测试 | 围绕"孩子乱按遥控器""家长改配置"两类角色自由探索，每轮 1h，记录缺陷与新用例 | — |

### 3.2 测试方法与设计依据

- **等价类划分**：登录态（游客/已登录）、配置来源（4级）、字幕来源（CC英中/AI/仅中/仅英/无轨）、网络（正常/弱/断）；
- **边界值分析**：ep 越界、version 相等/回退/递增、URL 协议前缀、搜索空串/纯空格/超长串、二维码 180s 过期临界；
- **状态迁移**：二维码登录状态机（861未扫→86090已扫→0成功 / 860过期）、播放器状态（解析→起播→DASH失败→降级MP4→失败→重试→ENDED→连播/结束）；
- **错误推测**：BV 下架、直链过期 403、接口风控、半截缓存 JSON、模型解压中断、配置索引失效；
- **场景矩阵**：见 3.4，核心链路必须在矩阵的每个组合至少跑通一次。

### 3.3 用例优先级定义

| 级别 | 定义 | 执行要求 |
|---|---|---|
| P0 | 破坏产品三底线（白名单/永远有片单/零门槛）或核心播放链路不可用 | 每轮 100% 执行，通过率必须 100% |
| P1 | 主要功能、主要异常降级路径、性能与兼容基线 | 每轮 100% 执行，通过率 ≥95% |
| P2 | 次要功能、UI 细节、极端边界 | 一轮/回归抽测，通过率 ≥80% |

### 3.4 关键场景矩阵（回归必跑组合）

| 维度 | 取值 |
|---|---|
| A 登录态 | A1 游客 / A2 已登录普通账号 |
| B 拉流路线 | B1 DASH 成功（A2）/ B2 DASH 失败自动降级 MP4 / B3 MP4 直链（A1） |
| C 字幕 | C1 CC英中轨 / C2 仅中文轨 / C3 AI轨（需A2）/ C4 无任何轨（Vosk）/ C5 无轨且自动字幕关闭 |
| D 网络 | D1 正常 / D2 启动时断网 / D3 播放中断网 / D4 弱网（限速） |
| E 配置来源 | E1 自定义地址 / E2 内置默认地址 / E3 离线内置 / E4 本地缓存（版本回退保护） |

最小回归集：{A1B3C4D1E3、A2B1C1D1E1、A2B2C3D4E1、A1B3C2D2E4、A2B1C5D1E2} 共 5 条端到端链路（启动→浏览→搜索→详情→播放→字幕→连播→退出）。

### 3.5 准入标准（Entry Criteria）

1. 被测版本构建成功（本地 `gradle assembleDebug` 或 CI 产物），版本号明确；
2. 冒烟用例（P0 前 10 条：CFG-001/002、MAIN-001、PLY-001/002、SUB-001/002、QR-003、SAFE-001、CI-001）手工预跑通过；
3. 测试环境就绪（见第 4 章），测试账号、测试配置文件（含异常配置）已备好。

### 3.6 准出标准（Exit Criteria）

1. P0 用例执行率 100%、通过率 100%；P1 执行率 100%、通过率 ≥95%；P2 通过率 ≥80%；
2. 无未关闭的 S1/S2 缺陷；S3 缺陷遗留 ≤3 个且均有规避方案和排期；
3. 整轮测试崩溃（crash/ANR）次数为 0；
4. 3.4 场景矩阵 5 条端到端链路全部通过；
5. 输出《测试报告》（用例执行统计 + 缺陷清单 + 遗留风险）。

### 3.7 暂停与恢复

- 出现 S1 缺陷阻塞大面积测试（如构建失败、启动崩溃）时暂停，转开发修复，修复版本回归冒烟后恢复；
- B 站接口或登录协议变更导致批量用例无法执行时，暂停相关组，其余组继续。

## 5. 风险与应对

| # | 风险 | 等级 | 应对 |
|---|---|---|---|
| R1 | B 站 web 接口/登录协议变动或风控升级，导致解析/拉流批量失败 | 高 | 接口层用例（L2）每日冒烟；失败先 curl 复测接口本身，区分"客户端缺陷"与"外部变更"，后者提变更单不计缺陷 |
| R2 | B 站限流（大量搜索解析）影响测试执行节奏 | 中 | resolve 缓存使大部分播放不走搜索；批量解析类用例分散执行、加间隔 |
| R3 | 无大会员账号，4K 路径无法实测 | 中 | 仅做代码走查确认 qn 请求参数固定最高档，COMP-008 标记"有条件执行" |
| R4 | 真机 65寸电视不可得，大屏适配结论只能基于模拟器 | 中 | 用模拟器 4K 分辨率 + sw600dp 断言替代，标注结论局限性 |
| R5 | 片单索引（catIdx/itemIdx）在配置更新后失效：旧搜索结果/详情页持有旧坐标，点击可能进入错误条目或被 finish 兜底 | 中 | DTL-008 验证兜底；作为已知设计限制写入测试报告，不按缺陷处理（符合"永不出错崩溃"底线） |
| R6 | 二维码登录依赖真实手机扫码，自动化困难 | 低 | 该组用例人工执行；其余组可脚本化 |
| R7 | release 无签名配置，无法验发布包 | 低 | CI-004 记录为工程问题，测试以 debug 包为准 |

## 7. 缺陷管理

### 7.1 严重等级定义（结合本产品）

| 等级 | 定义 | 本产品示例 |
|---|---|---|
| S1 致命 | 破坏三底线或崩溃/ANR/无法使用 | 白名单外内容可被访问；主界面崩溃；任意片子都无法播放；断网后片单为空 |
| S2 严重 | 主要功能失效，无替代路径 | 扫码登录永远失败；DASH 与 MP4 双路均失败；连播失效；自动降级不生效 |
| S3 一般 | 功能可用但有明显问题 | 字幕不同步/样式错乱；搜索拼音部分失效；设置项状态显示错误；起播时间超标 |
| S4 轻微 | UI/文案/体验问题 | 卡片描边异常；toast 文案错别字；焦点动画卡顿 |

### 7.2 缺陷生命周期

`新建 → 确认（负责人 triage）→ 修复中 → 待回归 → 关闭`；拒绝/延后需注明理由并经测试负责人确认，延后项进入遗留风险清单。

### 7.3 缺陷单必填字段

编号、标题、严重等级、优先级、复现环境（设备/网络/登录态/配置来源）、复现步骤（可含 adb 命令与 logcat 片段）、预期 vs 实际、复现概率、附件（截图/录屏/日志）。
